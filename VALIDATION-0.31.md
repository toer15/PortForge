# PortForge 0.31 / Engine 1.14 startup compatibility

The reported Zelda Breath of the Wild 1.0.0 crash occurred in IStorage.Read: the destination was 0x300100cf0 after its older SDK truncated a stack pointer in the engine's 39-bit layout (0x1300100cf0). The game's NPDM requests type 1, a 36-bit address space. The runtime previously selected its alternate memory layout only for AArch32 modules and ignored this AArch64 request.

The runtime now reads NPDM before memory initialization and chooses the 36-bit layout for type 1. Code, stacks and kernel allocations stay in the low region; alias and heap allocations remain within 36 bits. Type 3 retains the prior 39-bit layout. No game-code ABI fields changed. Reference for the 36-bit code/stack/kernel region relationship: [Atmosphere's process address-space layout](https://github.com/Atmosphere-NX/Atmosphere/blob/master/libraries/libmesosphere/source/kern_k_page_table_base.cpp).

Zelda also contains about 40,000 extracted assets. Startup previously attempted to map every one; only about 7,900 fit the mapping descriptor allowance on this PC. The engine now makes at most 1,024 startup mapping attempts, prioritizes ExeFS and a packed RomFS image, marks the whole shared tree read-only, and uses the existing bounded on-demand reader for other assets. This bounds eager file opens; directory indexing still occurs.

After the memory fix, Zelda passed its original crash but presented black frames. Profiling found a constructor repeatedly executing LDXR X followed by STXR W at the same address. The translator required equal sizes, so its retry loop never completed. Both reference helpers and LLVM translation now permit a narrower single store within the loaded reservation. Pair stores remain exact, widening fails, and the compare-and-swap still rejects competing writes. The JIT cache key has a new IR revision to discard stale translated units. Existing AOT modules need one rebuild for this change; new conversions include it automatically.

Checks cover 36-bit pointer round-tripping and unchanged 39-bit regions; bounded mapping, read-only protection and on-demand reads; and the mixed-width operation through the real JIT plus reference helper. The exclusive-instruction differential check exercises 160 instruction words and 1,280 states with no mismatches. Game testing uses isolated copies and separate saves.

Nine selected engine suites pass: memory_layout, ipc_message, five filesystem suites plus the tree suite, and jit_service. Mario's existing AOT module starts with the 39-bit layout and produced 747 frames in the short headless smoke test. Zelda's rebuilt module passed the original crash and black-screen block, displayed the opening title/cutscene and loaded its audio; a captured frame shows the "Breath of the Wild" opening. The first windowed test ended through normal Exit before its unattended time limit, so the final runtime is also checked headlessly to avoid desktop keyboard input. These are startup checks on this PC, not a promise of full-game compatibility or instant loading on all PCs.

The final headless Zelda run completed its 65-second limit with exit 0 and 1,477 frames, continuing to load opening-world assets. It loaded no stale JIT units after the cache-key revision. Existing player saves were not used for the isolated checks.
